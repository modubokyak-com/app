## 0. 14일 테스트 규칙 (먼저 알아야 할 것)

- 비공개 테스트에 **테스터 12명 이상이 14일 동안 끊기지 않고 참여(opt-in 유지)** 해야 프로덕션 접근을 신청할 수 있다. 중간에 누가 빠져서 11명이 되면 그날부터 다시 센다.
- 테스터는 Google 계정 이메일 목록 또는 Google 그룹으로 등록한다. 테스터가 **참여 링크를 눌러 수락하고 설치**까지 해야 센다.
- 테스트 중에 새 빌드를 올려도 14일 카운트는 유지된다. 올리는 것은 오히려 권장(실제 사용 흔적).
- 14일이 지나면 Console에 "프로덕션 액세스 신청" 버튼이 열리고, 설문(무엇을 테스트했나, 테스터 피드백, 고친 것)에 답하면 구글이 보통 7일 안에 결정한다.
- 비공개 테스트 출시도 **심사를 받는다**(가볍지만 정책 위반이면 거절). 그래서 내부 테스트와 달리 아래 2절의 선언·등록정보가 전부 필요하다.
- 팀 메모의 **"10월 9일 10:34 이후 제출"**: Console에 떠 있는 시각이면 그때까지는 신청 버튼이 안 열린다는 뜻. 화면 캡처해 두고, 그 전에 테스터 12명을 채워 두면 날짜가 겹쳐 손해가 없다.

### 4.1 테스터에게 보낼 시나리오 (5분)

4. 하루 한 번 알람 응답. 이상하면 화면 캡처해서 단톡방에.
5. **14일 동안 앱을 지우거나 테스트 나가기를 누르지 않기.**

## 5. 전체 화면 인텐트 시연 영상

Console 신고에 필요. 30초~1분, 세로, 실기기 녹화, 테스트 데이터로.

1. 홈에 알람이 2분 뒤로 등록된 모습 → 2. 화면 끄고 잠금 → 3. 알람이 잠금 화면 위로 뜸(약 이름, **버튼 3개**: 지금 약 먹기 / 안 먹고 건너뛰기 / 잠시 미루기) → 4. "지금 약 먹기" → 완료 화면 → 홈.

자막에 "보호자", "음성", "AI" 금지. YouTube 비공개(링크 공개) 또는 Drive 링크.

## 6. 알림 구현 상태 (팀 목록 4번을 코드로 대조)

| 상태 | 항목 | 코드 사실 |
|---|---|---|
| ☑ | 알림 권한 요청·거절 안내 | 저장 시 요청, 거부하면 "알림이 꺼져 있어요 → 설정 열기" + 홈 배너 |
| ☐ | 채널 차단 감지 | 미구현(3절 선택 항목) |
| ☑ | 정확한 알람 권한 철회·재허용 | 홈 배너. 없으면 비정확 예약으로 폴백. 재허용 후 앱 열면 `resyncAllAlarms`(앱 시작·포그라운드 복귀 시) |
| ☑ | USE_EXACT_ALARM | 미사용. SCHEDULE_EXACT_ALARM만 |
| ☑ | 상시 서비스 | 없음 |
| ☑ | 재부팅·시간·시간대 변경 | `AlarmBootReceiver` → HeadlessJS 재예약 |
| ☑ | 수정·삭제 시 옛 알림 | `cancelSchedule(id)`. id가 일정별이라 동시 알람도 덮어쓰지 않음 |
| ☑ | 강제 종료 | OS가 알람 삭제(정상). 앱 재실행 시 재예약. "최근 앱 지우기"는 영향 없음 |
| ☑ | 반복 방식 | 반복 트리거 없이 매 회차 "다음 1회"만 예약, 울린 직후 다음 회차 재예약 |
| ☐ | 잠금화면 노출 | PUBLIC, 약 이름 표시(3절 결정) |

## 7. 실기기 검증 (내부 테스트 빌드로, 비공개 테스트 올리기 전)

Android 14 이상 1대 포함.

| ☐ | 확인 | 기대 |
|---|---|---|
| ☐ | 첫 실행 → 이름 → 알람 설정 | 알림 권한 요청, 거부 시 안내 + 홈 배너 |
| ☐ | 권한 거부 → 설정에서 허용 → 복귀 | 배너 사라짐, 다음 알람 울림 |
| ☐ | Android 14+ 정확한 알람 | 배너 → 설정 → 켬. 끈 상태도 울리되 늦을 수 있음 |
| ☐ | 잠금 화면 알람 | 전체화면, 소리 반복, 버튼 3개, 되돌리기 8초 |
| ☐ | 화면 꺼짐·절전·하루 미사용 | 정시 울림. 제조사 절전은 안내로만 |
| ☐ | 알람 3분 방치 | 소리는 멈출 수 있음, 알림은 남음 |
| ☐ | 재부팅 / 시간대 변경 / 23:50 알람 자정 넘김 | 다음 회차 재예약 |
| ☐ | 약 수정·삭제 | 옛 시각 안 울림 |
| ☐ | 같은 시각 약 2개 | 둘 다 옴 |
| ☐ | 강제 종료 후 | 안 울림(정상) → 앱 열면 복구 |
| ☐ | 비행기 모드 | "불러오지 못했어요 + 다시 시도", 점검은 "인터넷에 연결되지 않았어요" |
| ☐ | 서버 오류 중 응답 | "저장에 실패했어요", 성공으로 표시 안 됨 |
| ☐ | 1분 점검 | `docs/qa-quick-check-cases.md` A1·B1·B8·C1·D4·E1 |
| ☐ | 사진 등록 / 카카오 복구 / 처음으로 확인창 / 모든 데이터 삭제 | 각 1회 |
| ☐ | 글꼴 최대 · 다크 모드 | 잘림·깨짐 없음 |
| ☐ | 사전 출시 보고서 | 크래시·접근성 경고 확인 |

## 8. 14일 뒤 — 프로덕션 접근 신청 설문 (답 초안)

Console → 대시보드 → "프로덕션 액세스 신청". 이렇게 답한다.

- **테스트 기간·인원**: 비공개 테스트 트랙에서 N명이 14일(날짜~날짜).
- **어떻게 모집·소통했나**: 팀원·가족·지인, 카카오 단톡방/Google 폼으로 피드백.
- **무엇을 테스트했나**: 복약 알람(잠금 화면 전체화면, 권한 거부·재허용, 재부팅), 1분 복용 점검, 약봉투 사진 등록, 데이터 삭제.
- **받은 피드백과 반영**: (실제 피드백 3~5개와 고친 빌드 버전).
- **출시 준비가 됐다고 보는 이유**: 크래시 0, ANR 0(vitals 캡처), 등록정보·선언 완료.
- 승인되면 → 프로덕션 트랙에 같은 AAB 승격 → 심사(1~7일) → 출시.
