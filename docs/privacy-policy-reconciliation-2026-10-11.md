- 공개 페이지 시행일은 2026-10-11이며 회사명과 `official@modubokyak.com`이 표시된다.
- 공개 HTML 저장소는 `modubokyak-com/web`이다. 저장소 README는 HTML이 생성 결과물이고 직접 수정하지
  말라고 명시한다. 생성 원본(`store-assets/common/*.html`)과 빌드 스크립트는 이 컴퓨터에서 찾지 못했다.
- 앱의 기존 개인정보 화면은 로그인 전 서버 전송, 약 설명용 OpenAI 전송, Supabase 중계, Apple 이메일
  미수집, 익명 집계의 삭제 제외를 정확히 설명하지 못했다. 작업 브랜치에서 이 사실관계의 수정안을 만들었다.

## 공개 웹 원본에서 고쳐야 할 단정

다음 문구는 운영 계약/설정을 확인한 뒤 확정한다. 확인 전에는 앱·웹·Data safety에서 약속하지 않는다.

1. 모든 삭제가 “즉시” 완료되고 “되살릴 수 없다”는 표현: Supabase/Auth/수탁사 로그와 백업 삭제 시점 확인 필요.
2. OpenAI가 최대 30일만 보관하고 학습에 사용하지 않는다는 표현: 실제 조직·프로젝트의 계약과 데이터
   제어 설정 확인 필요.
3. 사진이 처리 직후 완전히 폐기된다는 표현: 앱 DB 저장 코드는 없지만 Supabase Edge Function/OpenAI의
   요청 로그와 보관 설정 확인 필요.
4. Supabase 서울 리전 및 OpenAI가 특정 국가에서 처리한다는 표현: 현재 프로젝트 리전·계약상 처리 위치와
   국외 이전 고지 요건 확인 필요.
5. 모든 통신과 저장이 암호화된다는 표현: 코드 URL은 HTTPS지만 SDK·리디렉션·로컬 저장·백업까지
   포함한 범위를 먼저 확정해야 한다. 앱의 AsyncStorage 건강 관련 초안에는 앱 자체 암호화가 없다.
6. “서버 접근 권한을 단계적으로 강화”한다는 과거형 설명: 2026-10-11 운영 RLS lockdown이 확인됐으므로
   현재 상태를 반영하되 독립 보안 검토를 받은 것으로 표현하지 않는다.

## 계정 삭제 페이지 정합성

- 앱은 인증 세션으로 `delete_my_account` RPC를 호출하고, 서버 성공 후에만 기기 알람·로컬 데이터·세션을
  정리한다. 실패하면 성공 메시지를 표시하지 않는다.
- 운영 DB에서 인증 사용자의 삭제 실행 권한과 RPC/FK가 유지된 것은 확인했다. 실제 서비스 계정과 백업을
  삭제하는 종단간 시험은 하지 않았다.
- 계정과 연결되지 않은 `voice_guide_events` 집계는 계정 삭제 cascade 대상이 아니다. 공개 페이지가 이를
  제외한다고 밝힌 현재 방향은 코드와 맞지만 보관 기간은 별도 결정해야 한다.
- 앱 삭제나 로그아웃만으로 서버 계정이 삭제되지 않는다는 안내는 코드와 맞다.
- 카카오·Apple 제공자 계정 또는 연결 정보 삭제 범위는 앱의 자체 계정 삭제와 구분해 안내한다.

## 생성 원본에 반영할 앱 기준 문구

작업 브랜치의 `care-app/src/lib/privacyPolicy.ts`를 비교 기준으로 쓴다. 특히 아래 내용을 웹에도 포함한다.

- 로그인 전 1분 점검도 약·영양제 이름, 연령대, 선택 건강 상태를 Supabase RPC로 전송하지만 계정 결과로
  저장하지 않는다는 구분.
- 사진은 Supabase Edge Function을 거쳐 OpenAI로 전송되며, 서버에 없는 약 설명을 선택하면 약 이름도
  같은 경로로 전송된다는 설명.
- Apple 로그인은 식별값과 허용한 이름만 요청하고 이메일 scope는 요청하지 않는다는 현재 코드 상태.
- 계정 삭제 성공 시 삭제하는 계정 연결 데이터와, 식별값 없는 집계가 삭제 대상이 아니라는 구분.
- 문의 주소 `official@modubokyak.com`, 회사명 `주식회사 안팜(AhnPharm Inc.)`, 시행일 2026-10-11.
